# Geoapify provider contract fixtures

Captured on 2026-10-02 using three real Geoapify requests. JSON was pretty-printed;
the successful responses retain their complete provider structure, unknown
fields, datasource attribution and licence information. No API key is stored.

| Original fixture | Request (API key omitted) |
| --- | --- |
| `autocomplete-warszawa-pl.json` | `GET /v1/geocode/autocomplete?text=Warszawa&type=city&limit=10&lang=en&format=json&bias=countrycode:pl` |
| `autocomplete-cambridge-no-bias.json` | `GET /v1/geocode/autocomplete?text=Cambridge&type=city&limit=10&lang=en&format=json&bias=countrycode:none` |
| `place-details-warsaw.json` | `GET /v2/place-details?id=<first Polish city from the Warszawa response>&features=details&lang=en` |

Failure fixtures are deliberately derived from those captured responses, not
presented as unmodified provider responses:

- `autocomplete-empty.json`: the Warszawa response with `results` replaced by an empty array.
- `place-details-without-details.json`: the Warsaw response with `feature_type` changed from `details` to `unsupported`.
- `place-details-invalid-timezone.json`: the Warsaw response with `timezone.name` changed to `Invalid/Timezone`.

Missing/null timezone objects and missing/null/blank/invalid/offset names are
generated by changing only the relevant field of the full Place Details fixture
in memory. HTTP errors and artificial delays are generated by WireMock; they do
not require additional calls to Geoapify.

WireMock reads response bodies from `__files/`. The server runs on a random local
port and the real production HTTP configuration always receives `test-api-key`.
The fixture payload's `place_id` in Place Details differs from the selected
autocomplete identifier: the adapter intentionally retains the requested ID in
ResolvedCity, matching the established resolve contract.

The Warszawa response contains one `suburb` result despite `type=city`; the
contract test verifies its removal and preserves the order of all remaining
cities, including the US result. Country bias is not a country filter.

Run offline adapter tests (no database or real key required):

```bash
./mvnw -Dtest=GeoapifyCityLookupClientOfflineIntegrationTest test
```

Normal `./mvnw clean verify` excludes `@Tag("external")`. To compare the captured
contract with the provider, supply `GEOAPIFY_API_KEY` and run the small optional
external suite against a current test database:

```bash
./mvnw -Dtest=GeoapifyLookupClientIntegrationTest -DexcludedGroups= test
```
